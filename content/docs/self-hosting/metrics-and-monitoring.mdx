## Health checks

Both are on the public port, need no authentication and never return error details.

| Endpoint | Returns |
|---|---|
| `GET /health/live` | `200 {"status":"ok"}`, without touching the database. Use it for restarts. |
| `GET /health/ready` | `200` only when every check passes, `503` otherwise. Use it for load-balancer membership and the container health check. |

```json
{"status": "ready", "checks": {"database": "ok", "schema": "ok", "web": "ok"}}
```

- `database`: a pooled connection answered within 2 seconds.
- `schema`: the database's migrations match this binary exactly (`unknown` if the database is unreachable). A release whose migrations haven't been applied stays unready.
- `web`: `disabled` without `GATEWAY_WEB_DIR`; otherwise the dashboard's files are still there.

Inside the container, which has no shell or `curl`, the image's health check runs `open-model-gateway healthcheck`, which asks `/health/ready` over loopback and exits 0 or 1. Kubernetes can probe the two endpoints directly with `httpGet`. See [Container health checks](/docs/self-hosting/container#health-checks).

Probe `/health/ready` from outside as well, since metrics can't tell you the public address is reachable.

## Metrics

Set `GATEWAY_METRICS_ADDR` (for example `127.0.0.1:9464`) to serve Prometheus metrics on a **separate** listener: `GET /metrics` in OpenMetrics format, everything else `404`. It has no authentication, so keep it on loopback or a private scrape network, and never route your proxy to it.

Labels are deliberately few: route templates (not raw paths), provider kinds and configured model names (at most 200 each, then `other`), and safe error codes. No workspace, key, user or request ids, and nothing from prompts or responses.

| Metric | Type | Labels |
|---|---|---|
| `gateway_build_info` | gauge | `version` |
| `gateway_http_requests_total` | counter | `method`, `route`, `status` |
| `gateway_http_request_duration_seconds` | histogram | `method`, `route` |
| `gateway_inference_attempts_total` | counter | `provider`, `model`, `outcome` |
| `gateway_inference_attempt_errors_total` | counter | `provider`, `code` |
| `gateway_upstream_duration_seconds` | histogram | `provider`, `model` |
| `gateway_upstream_time_to_first_token_seconds` | histogram | `provider`, `model` |
| `gateway_inference_tokens_total` | counter | `provider`, `model`, `direction` |
| `gateway_settlements_total` | counter | `outcome` (`settled`, `unknown`, `held`). From v0.5.0, `held` also counts settlement writes that time out after 3 seconds, the usual case during a database outage. |
| `gateway_admission_seconds` / `gateway_settlement_seconds` | histogram | `phase`, `outcome`. Time spent in each phase of admission and settlement, including lock waits; see [Scaling](/docs/self-hosting/scaling#metrics-and-monitoring). |
| `gateway_scope_lock_wait_seconds` | histogram | `lock` (`authority`, `rows`), `path` (`admission`, `settlement`). Time waiting for a workspace's or key's own scope locks; a rising `rows` tail means one scope is approaching its ceiling. |
| `gateway_scope_lock_waiting` | gauge | `path`. Governance transactions on this replica waiting for a scope lock right now. |
| `gateway_lock_deadlock_retries_total` | counter | `path`. Should stay at 0; a rise means a hand-written session changed scopes out of canonical order. |
| `gateway_cache_lookups_total` | counter | `cache`, `result` (`hit`, `miss`, `bypass`) |
| `gateway_config_changes_total` / `gateway_config_poll_failures_total` / `gateway_config_listener_up` | counter / counter / gauge | Per-replica configuration cache freshness. |
| `gateway_work_leases_held` / `gateway_work_lease_terms_total` / `gateway_background_runs_total` | gauge / counter / counter | Which replica holds each singleton background job's lease, and its outcomes. |
| `gateway_history_partition_months_ahead` | gauge | `table`. Future monthly partitions still available; an alert fires below 2. |
| `gateway_usage_rollup_hours_total` | counter | Hourly usage rollups computed. |
| `gateway_history_verify_findings` | gauge | Findings from the hourly `history_verify` job; should stay at 0. |
| `gateway_admission_denials_total` | counter | `code`, `scope` (`installation` no longer occurs: installation-wide limits were removed in v0.4.0) |
| `gateway_reservations_held` | gauge | `state` (`pending`, `unknown`) |
| `gateway_alert_evaluations_total` | counter | `result` |
| `gateway_alert_rule_failures_total` | counter | |
| `gateway_db_pool_connections`, `gateway_db_pool_max_connections` | gauge | `state` |
| `gateway_metrics_collection_errors_total` | counter | `collector` |
| `gateway_file_store_operations_total` | counter | `backend`, `op`, `outcome` |
| `gateway_file_store_bytes_total` | counter | `backend`, `op` |
| `gateway_batches` | counter | `mode`, `event` |
| `gateway_batch_lines` | counter | `mode`, `provider`, `outcome` |
| `gateway_batch_queue_depth` | gauge | `mode` |
| `gateway_batch_workers` | gauge | `state` |
| `gateway_batch_route_lines` | gauge | `provider`, `state` (`waiting`, `running`) |
| `gateway_batch_paused_routes` | gauge | `reason` |
| `gateway_batch_route_pauses_total` | counter | `reason` |
| `gateway_egress_denied_total` | counter | `purpose` (`provider`, `oidc`, `storage`, `catalog`, `smtp`, `audit`). Outbound connections the [address policy](/docs/self-hosting/security#the-outbound-address-policy) refused, counted when no allowed address remains. New in v0.6.0. |
| `gateway_auth_throttled_total` | counter | `endpoint` (`login`, `callback`), `reason` (`client_rate`, `pending_cap`). Sign-in steps refused by the [abuse controls](/docs/self-hosting/identity#sign-in-abuse-controls). No addresses or identities. New in v0.6.0. |
| `gateway_audit_export_deliveries_total` | counter | `outcome` (`delivered`, `failed`, `skipped`). Audit export requests; `skipped` counts events whose month was archived before they were delivered. New in v0.6.0. |
| `gateway_audit_export_rejected_records_total` | counter | Audit events an OTLP collector refused for good. They aren't retried. Resets when the replica restarts. New in v0.6.0. |
| `gateway_audit_export_queued` | gauge | Audit events waiting for the receiver to accept them. New in v0.6.0. |
| `gateway_audit_export_oldest_seconds` | gauge | Age of the oldest waiting audit event (0 when none). New in v0.6.0. |

Counters and most gauges are per replica: `sum` them. `gateway_reservations_held` counts the whole installation, so take the `max` across replicas.

## Alert rules and a dashboard

The repository's `deploy/monitoring/` has:

- `prometheus.example.yml`: a scrape configuration;
- `prometheus-rules.yml`: example alerts for metrics down, 5xx rate, p95 latency, held settlements, growing unknown reservations, a stuck pending floor, budget denials, capacity saturation, upstream failure rate, time to first token, pool saturation, alert-evaluator failures and collector errors (validated with `promtool`; thresholds are starting points);
- `grafana-dashboard.json`: a Grafana dashboard with overview, HTTP, inference, accounting and internals rows.

From v0.5.0 the `GatewaySettlementHeld` example alert also fires on settlement writes that time out. The example files have no rules yet for the v0.6.0 metrics: add the ones below yourself.

## Sign-in, egress and audit export

Starting points for the metrics new in v0.6.0:

| Alert on | Example | Means |
|---|---|---|
| Sign-in refused for everyone | `sum(rate(gateway_auth_throttled_total{reason="pending_cap"}[5m])) > 0` for 5 minutes | Too many sign-ins are pending installation-wide. Look for a flood of sign-in starts. |
| Refused destinations | `sum by (purpose) (increase(gateway_egress_denied_total[15m])) > 0` | Something tried to reach an address the policy refuses, such as a private, loopback or metadata address. A new failure after an upgrade usually means a private network is missing from `GATEWAY_EGRESS_PRIVATE_ALLOW`. |
| Audit export falling behind | `max(gateway_audit_export_oldest_seconds) > 900` | The oldest waiting audit event is over 15 minutes old: the receiver is down or refusing deliveries. |
| OTLP collector refusing events | `sum(increase(gateway_audit_export_rejected_records_total[15m])) > 0` | The collector refused events for good; receivers see the gap. |

The gateway's own database credentials could stop the audit export, so also alert at the receiver, on gaps and on silence. See [Audit export to a SIEM](/docs/self-hosting/audit-export#what-receivers-should-alert-on).

## When something fires

- **Held settlements**: the gateway couldn't record a result, or the write took over 3 seconds. Holds are kept, never refunded as zero. Fix the database first; expired holds become unknown, then review unknown usage. During a database failover this is expected: see [Kubernetes](/docs/self-hosting/kubernetes#failover-timing).
- **Unknown reservations**: they keep budget holds and can block budgeted requests (`unresolved_usage`). Resolve them with evidence; never delete reservations.
- **Capacity or pool saturation**: requests beyond `GATEWAY_MAX_CONCURRENT_REQUESTS` get `429`. From v0.4.0, admission locks a workspace's and a key's own rows rather than one installation-wide row, so adding replicas raises overall capacity; one workspace or key still tops out on its own rows by design. See [Scaling](/docs/self-hosting/scaling).
- **Upstream failures**: check the provider and the connection's credential. Routes that keep failing are skipped for their cooldown. If `gateway_egress_denied_total{purpose="provider"}` rises at the same time, the address policy refused the destination.
- **Audit export behind**: open Admin › Settings › Audit export for the last error. Nothing is dropped while it retries; events wait in the queue.

## Logs

The gateway logs JSON to standard error: request ids, methods, status and timing. Never prompts, bodies, query strings or credentials. Don't turn on trace-level logging of the AWS SDK or HTTP clients in production.
