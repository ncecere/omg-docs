title: Configuration
description: Every environment variable Open Model Gateway reads, with its default and allowed values.
---

The gateway reads its configuration from environment variables at startup. Invalid values stop startup with an error that names the variable, never its value. Most settings, such as providers, models, prices, limits and email, live in the dashboard instead; these variables cover what must exist before the database can be read, and secrets.

On startup the gateway also loads a `.env` file from its working directory if there is one, or the file named by `GATEWAY_ENV_FILE`.

## Secrets from files

Four secrets can be read from a file instead: set `DATABASE_URL_FILE`, `GATEWAY_OIDC_CLIENT_SECRET_FILE`, `OPENAI_API_KEY_FILE` or `ANTHROPIC_API_KEY_FILE` to the file's path, such as a Compose or Kubernetes secret mount. The binary reads them itself at startup, in a container or not, before the `.env` file. One trailing newline is removed.

From v0.3.1, startup stops if, for any of those four:

- both the variable and its `_FILE` are set (even to an empty value);
- the value is empty, longer than 4,096 bytes, or contains a line break or NUL.

The error names the variable and the reason, such as `secret configuration: OPENAI_API_KEY: secret must not be empty`, never the value. An empty variable left exported in your shell is enough to trigger it: unset it rather than setting it to `""`. Values loaded from a `.env` file aren't checked this way. Other `_FILE` variables are not read.

## Core

| Variable | Default | Meaning |
|---|---|---|
| `DATABASE_URL` | (required) | PostgreSQL connection URL. Use the runtime role for `serve` and the migrator role for `migrate`. Or set `DATABASE_URL_FILE` ([secrets from files](#secrets-from-files)). |
| `GATEWAY_LISTEN` | `127.0.0.1:8080` (container: `0.0.0.0:8080`) | Address and port to listen on. |
| `GATEWAY_ENV` | `production` | `production` or `development`. Development allows plain-HTTP sign-in on loopback addresses only. |
| `GATEWAY_PUBLIC_URL` | unset | The browser-visible origin, such as `https://ai.example.edu`. Needed for sign-in; also used in invitation and alert emails. |
| `GATEWAY_WEB_DIR` | unset (container: `/app/web`) | Directory of the built dashboard. Unset serves the APIs only. An invalid directory stops startup. |
| `GATEWAY_ENV_FILE` | unset | Load this file instead of `./.env`. |
| `GATEWAY_DATABASE_MAX_CONNECTIONS` | `10` | Database pool size per replica, 2 to 500. |
| `GATEWAY_MAX_CONCURRENT_REQUESTS` | `128` | Inference requests at once per replica, 1 to 10,000. Beyond it: `429`. |
| `GATEWAY_REQUEST_TIMEOUT_SECONDS` | `120` | Inference deadline, 1 to 3,600 seconds, including time waiting for admission. |
| `GATEWAY_METRICS_ADDR` | unset (off) | Separate Prometheus listener, such as `127.0.0.1:9464`. Must differ from `GATEWAY_LISTEN`. |
| `RUST_LOG` | `open_model_gateway=info` | Log filter. Logs are JSON on standard error. |

## Scaling

New in v0.4.0; none of these change an existing default. See [Scaling](/docs/self-hosting/scaling) for what each one is for.

| Variable | Default | Meaning |
|---|---|---|
| `GATEWAY_ADMISSION_MODE` | `scoped` | `global` restores the pre-v0.4.0 installation-row admission protocol, as a one-release rollback. Any other value fails startup. |
| `GATEWAY_CONFIG_CACHE` | `on` | `off` turns off per-replica caches of pre-admission reads (no `LISTEN` connection, no version poll). Admission always re-checks live either way. |
| `GATEWAY_LISTEN_DATABASE_URL` | `DATABASE_URL` | The one session connection per replica that `LISTEN`s for configuration changes. Point it at PostgreSQL directly (never a transaction-mode PgBouncer). |
| `GATEWAY_REPORTING_DATABASE_URL` | unset | An optional read-only reporting replica (or pooler) for reports, usage and logs only, never for admission or settlement. |
| `GATEWAY_REPORTING_MAX_LAG_SECONDS` | `30` | A reporting replica replaying WAL further behind than this is skipped in favour of the primary. |
| `GATEWAY_PARTITIONS_AHEAD_MONTHS` | `3` (2–12) | Future month partitions `serve` keeps created ahead of time. |
| `GATEWAY_USAGE_ROLLUPS` | `auto` | `off` answers every usage read from raw history instead of the hourly rollups (same results, slower). |
| `GATEWAY_HISTORY_RETENTION_MONTHS` | `25` (1–1200) | Months `archive partition` keeps hot before an operator can detach them; `--retention-months` overrides it per call. |

## Sign-in

| Variable | Default | Meaning |
|---|---|---|
| `GATEWAY_OIDC_ISSUER` | unset | Your identity provider's exact issuer URL. |
| `GATEWAY_OIDC_CLIENT_ID` | unset | The registered client id. Without issuer and client id, sign-in is off. Setting only some sign-in variables stops startup. |
| `GATEWAY_OIDC_CLIENT_SECRET` | unset | For confidential clients. Or set `GATEWAY_OIDC_CLIENT_SECRET_FILE`. |
| `GATEWAY_OIDC_GROUPS_CLAIM` | `groups` | The ID-token claim that lists groups. A dotted path reaches into nested claims. |
| `GATEWAY_SCIM_TOKEN_ENV` | unset (SCIM off) | The **name** of the variable holding the SCIM bearer token (32 to 1,024 printable characters). Needs OIDC. |

### Sign-in limits and sessions

New in v0.6.0.

| Variable | Default | Meaning |
|---|---|---|
| `GATEWAY_TRUSTED_PROXIES` | unset | Comma-separated addresses or CIDR networks of your reverse proxies, such as `10.42.0.0/16`. Only a request from one of them has its `X-Forwarded-For` believed. Used for sign-in rate limits only. |
| `GATEWAY_LOGIN_RATE_PER_MINUTE` | `60` | Sign-in starts, and separately callbacks, allowed per client address per minute, per replica. 1 to 10,000. |
| `GATEWAY_SESSION_LIFETIME` | `12h` | How long a dashboard session lasts after sign-in. `15m` to `7d`, written as a whole number with `m`, `h` or `d`, such as `30m`, `12h` or `7d`. |
| `GATEWAY_SESSION_IDLE_TIMEOUT` | `2h` | How long a session lasts without activity. `off`, or `15m` up to the lifetime. With a lifetime under 2 hours and this unset, it equals the lifetime. |

- An address in `GATEWAY_TRUSTED_PROXIES` with host bits set (`10.42.0.1/16`), a bad prefix, or an IPv4 network written in IPv6 form stops startup.
- The two rate settings are read only when sign-in is configured. The session settings are checked even without OIDC, so a typo is never missed.
- An empty value for any sign-in variable stops startup: unset it instead.

See [Identity setup](/docs/self-hosting/identity).

## Credentials and network approvals

| Variable | Default | Meaning |
|---|---|---|
| `GATEWAY_SECRET_ENV_ALLOWLIST` | empty | Comma-separated names of environment variables that connections may reference as `env:NAME`. Anything not listed is refused. From v0.6.0 the email password has its own list ([below](#email)). |
| `GATEWAY_LOCAL_UPSTREAMS` | unset | JSON list of approved self-hosted endpoints and their pinned IP addresses: `[{"endpoint":"http://models.example.internal:8000/v1","addresses":["10.10.1.20"]}]`. Up to 64 endpoints, 16 addresses each. |
| `GATEWAY_AWS_PROFILE_ALLOWLIST` | empty | Comma-separated AWS profile names that Bedrock connections and the file store may use. |
| `GATEWAY_BEDROCK_ENDPOINT_ALLOWLIST` | empty | Comma-separated HTTPS origins of Bedrock VPC endpoints that connections may use. |

The provider keys themselves are ordinary variables with names of your choice, such as `OPENAI_API_KEY`, listed in the allowlist. `OPENAI_API_KEY` and `ANTHROPIC_API_KEY` can also come from files with `_FILE` ([secrets from files](#secrets-from-files)). See [Provider credentials](/docs/self-hosting/provider-credentials).

## Outbound connections

New in v0.6.0.

| Variable | Default | Meaning |
|---|---|---|
| `GATEWAY_EGRESS_PRIVATE_ALLOW` | unset (none) | Private networks the gateway may connect to, as comma-separated CIDRs or single addresses, such as `10.20.0.0/16,fd00:1::/32`. |

Every outbound connection follows one address policy: metadata, link-local and reserved addresses are always refused, loopback is allowed only with `GATEWAY_ENV=development`, and private addresses (RFC 1918, `100.64.0.0/10`, IPv6 unique-local) only inside this list. Public addresses are allowed. Approved self-hosted model servers in `GATEWAY_LOCAL_UPSTREAMS` keep their own pinned approval and need no entry here.

- The list is read before every command, `healthcheck` included. An invalid address or prefix, host bits set, or an IPv4 network written in IPv6 form stops them all.
- List an identity provider, S3-compatible store or AWS private endpoint on a private network, or sign-in (at startup) and those requests fail with a message that names this variable.
- Over Tailscale, list only the addresses you need, never all of `100.64.0.0/10`.

See [Security](/docs/self-hosting/security#the-outbound-address-policy).

## Email

New in v0.6.0. The relay itself (host, port, TLS, username and password reference) is set in Admin › Settings › Email; these variables decide what that page may use.

| Variable | Default | Meaning |
|---|---|---|
| `GATEWAY_SMTP_HOST_ALLOWLIST` | empty | Comma-separated SMTP relay hosts, as exact names or IP literals. The relay chosen in the dashboard must be listed. Empty: no email can be sent. |
| `GATEWAY_SMTP_SECRET_ENV_ALLOWLIST` | empty | Comma-separated names of variables the SMTP password reference (`env:NAME`) may read. |

- Hosts are compared without regard to case, a trailing dot or IPv6 spelling. Entries are hosts, not ports.
- An unlisted relay never gets a connection or the password. Settings › Email shows `host_not_allowed`.
- A listed relay on the same machine (`localhost`, `127.0.0.1`, `::1`) is allowed outside development too.
- Startup fails if a name is on both `GATEWAY_SMTP_SECRET_ENV_ALLOWLIST` and `GATEWAY_SECRET_ENV_ALLOWLIST`, or if the SMTP list names `DATABASE_URL`, `GATEWAY_OIDC_CLIENT_SECRET`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, or anything starting with `AWS_` or `GATEWAY_`.

## Audit export

New in v0.6.0. Set one destination at most: a webhook, syslog over TLS or an OTLP collector. See [Audit export to a SIEM](/docs/self-hosting/audit-export).

| Variable | Default | Meaning |
|---|---|---|
| `GATEWAY_AUDIT_WEBHOOK_URL` | unset | HTTPS endpoint the audit log is posted to, or `off`. |
| `GATEWAY_AUDIT_WEBHOOK_SECRET_ENV` | unset | The **name** of the variable holding the webhook signing secret, at least 32 bytes. Required with the webhook URL. |
| `GATEWAY_AUDIT_SYSLOG_URL` | unset | `syslog+tls://host[:port]` (port 6514 by default), or `off`. |
| `GATEWAY_AUDIT_SYSLOG_CA_FILE` | unset (public roots) | PEM file of the CA that signs the receiver's certificate. When set, only it is trusted. |
| `GATEWAY_AUDIT_SYSLOG_CLIENT_CERT_FILE`, `GATEWAY_AUDIT_SYSLOG_CLIENT_KEY_FILE` | unset | PEM client certificate and private key for mutual TLS. Both or neither. |
| `GATEWAY_AUDIT_OTLP_URL` | unset | An OpenTelemetry collector's full OTLP/HTTP logs endpoint, such as `https://collector.example.internal:4318/v1/logs`, or `off`. |
| `GATEWAY_AUDIT_OTLP_HEADERS_ENV` | unset | The **name** of the variable holding headers for the collector, `Key=Value,Key2=Value2`. Optional; OTLP only. |

Startup stops if:

- two of the three URLs are set, including `off` in one and a destination in another;
- a setting belongs to a transport that isn't in use, such as the webhook secret with only the syslog URL;
- a URL isn't HTTPS (plain HTTP is allowed only to loopback in development), or contains credentials or a fragment;
- the secret or headers variable is lower case, isn't set, is on `GATEWAY_SECRET_ENV_ALLOWLIST` or `GATEWAY_SMTP_SECRET_ENV_ALLOWLIST`, is one of the four [secrets from files](#secrets-from-files), or starts with `AWS_` or `GATEWAY_`;
- a syslog PEM file is missing, unreadable or over 1 MiB, or only one of the client certificate and key is set;
- the OTLP headers are malformed: more than 16, an invalid name, `Content-Type`, `Host` or `Content-Length`, or a value with anything other than visible ASCII and spaces.

Errors name the setting, never a secret, header or file content. `OTEL_*` variables are never read for the audit export.

## File store

| Variable | Default | Meaning |
|---|---|---|
| `GATEWAY_FILE_STORE` | `off` | `off`, `local` or `s3`. |
| `GATEWAY_FILE_ENCRYPTION_KEYS_ENV` | (required when on) | The **name** of the variable holding the master keys, `kid:base64key[,kid:base64key…]`. |
| `GATEWAY_FILE_STORE_DIR` | | `local`: an absolute directory owned by the gateway user, not readable by others. |
| `GATEWAY_S3_BUCKET` | | `s3`: the bucket (never created by the gateway). |
| `GATEWAY_S3_PREFIX` | none | Key prefix: path segments of `A-Z a-z 0-9 . _ -`. |
| `GATEWAY_S3_REGION` | `us-east-1` | AWS region, or a short code such as `auto` with a custom endpoint. |
| `GATEWAY_S3_ENDPOINT` | unset (AWS S3) | Exact origin of an S3-compatible store or AWS VPC endpoint. Must be in the allowlist below. |
| `GATEWAY_S3_ENDPOINT_ALLOWLIST` | empty | Comma-separated exact origins. An `http://` entry approves plain HTTP. |
| `GATEWAY_S3_FORCE_PATH_STYLE` | `true` with an endpoint, else `false` | Path-style addressing (MinIO, RustFS and Ceph usually need it). |
| `GATEWAY_S3_AUTH` | `aws:default` | `aws:default`, `aws:profile:<name>`, `aws:role:<role-arn>` or `static`. |
| `GATEWAY_S3_ACCESS_KEY_ID_ENV`, `GATEWAY_S3_SECRET_ACCESS_KEY_ENV` | | `static` only: the **names** of the variables holding the access key id and secret. |
| `GATEWAY_S3_CA_FILE` | none | PEM bundle of extra trust anchors for a private endpoint. |
| `GATEWAY_FILES_MAX_BYTES` | 200 MiB | Largest Files API upload, 1 KiB to 8 GiB. |

See [File storage](/docs/self-hosting/file-storage).

## Background work

| Variable | Default | Meaning |
|---|---|---|
| `GATEWAY_ALERT_INTERVAL_SECONDS` | `60` | How often alerts are evaluated, 0 to 86,400. `0` turns the evaluator off. |
| `GATEWAY_JOB_POLL_INTERVAL_SECONDS` | `30` | How often provider jobs (native batches, videos) are polled, 0 to 3,600. `0` turns polling off, and native batches stop being processed. |
| `GATEWAY_BATCH_WORKERS` | `4` | Gateway-run batch lines at once per process, 0 to 256. `0` turns the batch runner off. |
| `GATEWAY_BATCH_CONCURRENCY` | `2` | Lines of one batch at once, 1 to 64. |

Each route also has its own batch capacity and gates, set in the dashboard rather than with variables: see [Batch scheduling](/docs/administration/batch-scheduling). A route's server metrics URL must belong to an endpoint approved in `GATEWAY_LOCAL_UPSTREAMS`.

|---|---|

## AWS

Bedrock connections and the S3 file store with `aws:default` use the AWS SDK's standard credential chain (environment, web identity, container and instance roles, SSO). Endpoint overrides such as `AWS_ENDPOINT_URL` are deliberately **not** used.
