---
title: Upgrades
description: The upgrade procedure, why migrations are forward-only, rolling back, and notes for each release.
---

Every release can change the database schema. The gateway never migrates itself, and replicas of different releases can't share a database, so upgrades are a short, planned procedure.

## Procedure

<Steps>
<Step>

### Read the release notes

Check the [release](/docs/releases) for migrations, new settings and grant changes. Build or pull the image and note its digest.

</Step>
<Step>

### Back up

Take a backup and `verify` it. For releases with migrations, run a [restore drill](/docs/self-hosting/backups-and-restore#the-restore-drill) first.

</Step>
<Step>

### Stop traffic

Stop the proxy's traffic, then every gateway replica. Mixed-release replicas are not supported.

</Step>
<Step>

### Migrate and grant

As the migrator, run `open-model-gateway migrate` with the **new** binary, then reapply `deploy/staging/runtime-grants.sql`. (`python3 scripts/staging.py migrate` does both.)

</Step>
<Step>

### Start and check

Start the new release. Wait for `/health/ready` to show `schema: ok`, then check the metrics, a sign-in, and one small request.

</Step>
</Steps>

## Rolling back

- If **no migration ran**, redeploy the previous image by its digest.
- If a migration ran, restore the pre-upgrade backup **into a new database** and switch to it. There are no down migrations, and an older binary refuses a newer schema.

## Release notes

### To v0.4.0

**Migrations `0024` to `0036`**, the largest range since v0.1.0. Read [the release](/docs/releases/v0-4-0) before you upgrade: there are three breaking changes. Procedure:

1. **Back up** and verify it (`scripts/backup.py`). If you're upgrading from before `0033`, your existing backups are fine — only the *restore* path had a bug, and only for databases with reservations.
2. **Stop every gateway replica.** Mixed-schema replicas aren't supported, and three migrations briefly freeze history writes.
3. For a large installation, run `open-model-gateway partitions prepare` as the migrator **before** this maintenance window, so the heavy index builds happen online ahead of the drain.
4. Run `open-model-gateway migrate` as the migrator. Every step is resumable: an interrupted `migrate` picks up where it stopped.
5. **Reapply `deploy/staging/runtime-grants.sql`** (or let the Helm chart's migration job do it; see [Kubernetes](/docs/self-hosting/kubernetes#migration-job-and-runtime-grants)). This range adds several new grants — reapply the whole file even if some migrations add none.
6. Run `deploy/staging/verify-privileges.sql` to confirm the runtime role has exactly the expected privileges.
7. Run `open-model-gateway budget verify` (expect `mismatch_count: 0`, `rate_mismatch_count: 0`) and `open-model-gateway history verify` (expect `finding_count: 0`).
8. Start the new replicas, wait for `/health/ready`, then check sign-in and one bounded request.

- **Breaking: installation-wide budgets and rate limits are removed** (`0026`). Limits now exist only on workspace-type defaults, platform overrides, workspace caps and keys. `GET`/`PUT /platform/installation/policy` return `410 installation_limits_removed`. Any installation budget alert rule becomes a non-blocking **Installation spend** rule, keeping its thresholds and recipients. Move any shared ceiling you relied on into type defaults, overrides or keys before upgrading; workspaces may use more in total afterward.
- **Breaking: a budgeted request on an unbounded price returns `503 price_unbounded`, not `429 budget_exceeded`.** Unchanged from v0.3.2, repeated here because the admission path it runs through is rewritten this release.
- **Breaking: workspaces, keys, routes and cost centers can no longer be deleted, truncated or re-keyed, by any role** (`0034`). The product never did this — it disables, revokes and archives — so this mainly affects hand-written operator SQL, which now fails with a named check instead of a generic foreign-key error.
- Eight new environment variables, all optional with unchanged defaults: see [Configuration](/docs/self-hosting/configuration#scaling).
- New ids (requests, attempts, ledger entries, audit events) are UUIDv7 instead of UUIDv4: `x-request-id` values change shape, not format.
- A Kubernetes Helm chart is new and **beta**; see [Kubernetes](/docs/self-hosting/kubernetes).

See [Scaling](/docs/self-hosting/scaling) for what replicas, caches and partitions change in how the gateway runs.

### To v0.3.2

- No migrations and no new runtime grants. Rolling back to v0.3.1 is a redeploy of its digest.
- Routes on connections that can't serve their model are no longer accepted (`400 route_unsupported_capability`), but existing ones are kept. After upgrading, open Admin › Models and filter by **Not serving**; for each model, add a route on a connection that serves it and disable the unsupported route. See [Routes must be servable](/docs/administration/models-and-routes#routes-must-be-servable).
- Prices published through the management API must state every meter (`400 price_meters_incomplete`). Scripts that publish prices must add the missing meters as priced, not applicable or `unknown`.
- Budgeted requests on a price that can't bound them now get `503 price_unbounded` instead of `429 budget_exceeded`. Update alerts or dashboards that counted them as budget denials, and publish complete prices for the models concerned. See [Pricing](/docs/administration/pricing#prices-that-cant-bound-a-request).
- Chat Completions requests that send `max_tokens` now succeed instead of returning `400`.

### To v0.3.1

- No migrations and no new runtime grants. Rolling back to v0.3.0 is a redeploy of its digest.
- The image is distroless and has **no shell**. Replace health checks that run `sh`, `curl` or `wget` in the container with `["CMD", "/usr/local/bin/open-model-gateway", "healthcheck"]`, or Kubernetes `httpGet` probes. See [Health checks](/docs/self-hosting/container#health-checks).
- Remove any `--entrypoint container-entrypoint` override. Commands after the image name (`migrate`, `provision-user …`) work as before.
- An empty `DATABASE_URL`, `GATEWAY_OIDC_CLIENT_SECRET`, `OPENAI_API_KEY` or `ANTHROPIC_API_KEY` now stops startup, in a container or not. Unset unused ones instead of leaving them empty. See [Secrets from files](/docs/self-hosting/configuration#secrets-from-files).
- Clients that treated `404 model_not_found` as "routes are down" now get `503 model_temporarily_unavailable` with `Retry-After` in that case.

### To v0.3.0

- Migrations `0018` to `0022`. Reapply runtime grants.
- `0018` adds **jobs at once** to every limit layer, with type defaults of **2** active batch or video jobs per workspace. If workspaces run more at once, raise it in Admin › Settings › Defaults & limits.
- The [file store](/docs/self-hosting/file-storage) is new and **off** until you configure it. Files and batches need it. Each kind of file must then be allowed in Admin › Settings › Data & privacy.
- New workspace **Storage** limit, 1 GiB per workspace by default.
- `GATEWAY_MAX_BATCH_FILE_BYTES` and `GATEWAY_BATCH_MAX_OUTPUT_SCAN_BYTES` are no longer used (still checked at startup).
- New variables: `GATEWAY_FILE_STORE` and the `GATEWAY_S3_*` family, `GATEWAY_FILE_ENCRYPTION_KEYS_ENV`, `GATEWAY_FILES_MAX_BYTES`, `GATEWAY_BATCH_WORKERS`, `GATEWAY_BATCH_CONCURRENCY`.
- `0022` adds per-route [batch scheduling](/docs/administration/batch-scheduling) and adds no variables. Every route now runs at most **2 gateway-run batch lines at once** unless you change it in the route's **Batch scheduling** section; the other gates start off. Reapplied runtime grants cover the new tables. Batches admitted before `0022` keep a `24h` completion window.

### To v0.2.0

- Migrations `0011` and `0013` to `0017` (there is no `0012`). Reapply runtime grants.
- `0015` backfills budget totals from history; run `open-model-gateway budget verify` after migrating.
- New variables: `GATEWAY_ALERT_INTERVAL_SECONDS`, `GATEWAY_SCIM_TOKEN_ENV`, `GATEWAY_METRICS_ADDR`, `GATEWAY_DATABASE_MAX_CONNECTIONS`, `GATEWAY_JOB_POLL_INTERVAL_SECONDS`, `GATEWAY_MAX_BODY_BYTES_VIDEOS`, `GATEWAY_MAX_BATCH_FILE_BYTES`, `GATEWAY_BATCH_MAX_OUTPUT_SCAN_BYTES` and the `GATEWAY_REALTIME_*` family.

### v0.1.0

The first release of the single-enterprise gateway, on a new schema lineage (`0001` to `0010`). It can't upgrade a database from the earlier multi-organisation prototype: `migrate` refuses it. Start from an empty database.
