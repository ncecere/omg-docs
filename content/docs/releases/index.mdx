## Before 1.0

- **It is development software.** Each release is tested locally and in CI with mock providers and real PostgreSQL, plus a few small, capped checks against real providers. Production readiness, live identity-provider certification and load testing in your environment are your pilot's job.
- **Upgrades only go forward.** Migrations can't be undone by changing images; going back past a migration means restoring a backup. Read every release's notes between your version and the target. See [Upgrades](/docs/self-hosting/upgrades).
- **The management API may change** in any release. The inference API follows the vendor APIs it copies.

## How releases are published

- Each release is a Git tag, `vX.Y.Z`, on the main branch.
- From v0.3.0, each release publishes a signed container image to `ghcr.io/ncecere/open-model-gateway`, tagged `vX.Y.Z`, `vX.Y` (the newest patch of that minor version) and `latest-release` (the newest release). Images are signed with cosign keyless signing; check the signature (from v0.4.0 use **cosign v3.0 or newer**, since the signature is stored in its bundle format) and deploy by digest. From v0.3.1 the image is distroless, with no shell. See [Container and Compose](/docs/self-hosting/container#release-images).
- Each release's notes are also in the repository, in `docs/releases/` (for example `docs/releases/v0.3.2.md`), and the binary reports its release as the `version` of `gateway_build_info`.
- You can still build the image from the tag with the repository's `Dockerfile`. The manual publishing workflow pushes tested images of `main`, tagged with their full commit SHA, for staging.

## What's next

From the [roadmap](https://github.com/ncecere/open-model-gateway/blob/main/docs/roadmap.md), planned and not yet built: an OpenRouter video adapter, using uploaded files in chat requests, image edits and image input, content guardrails (designed, not yet built), native batches for more providers, more of the realtime interface, active health checks, key-expiry notifications and webhooks, and provider-invoice reconciliation. A plan, not a promise.
