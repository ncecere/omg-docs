Everything the Open Model Gateway dashboard does goes through the management API under `/api/v1`. It authenticates with **browser sessions** and, from v0.8.0, with **[admin API tokens](/docs/administration/admin-api-tokens)** for scripts. Inference API keys can never use it.

<Callout title="Pre-1.0">
  Routes may still change between releases before 1.0. From v0.10.0 the repository's OpenAPI document ([below](#openapi-documents)) describes every route and is checked against the running gateway, so check it against the release you run.
</Callout>

## Credentials

A management request carries exactly one credential:

| Credential | How it's sent | For |
|---|---|---|
| Browser session | The `omg_session` cookie set at sign-in | The dashboard |
| Admin API token | `Authorization: Bearer omg_admin_…` | Scripts, within the token's scopes ([Admin API tokens](/docs/administration/admin-api-tokens)) |

From v0.8.0, a request with two `Authorization` headers, or with an `Authorization` header and the session cookie (even a malformed one), is refused with `401` before either is examined. There is no fallback from one to the other. Make sure no proxy in front of the dashboard adds an `Authorization` header.

Some routes refuse every admin API token, whatever its scopes: workspace members, keys and other workspace-administration routes, admin token management, scheduled reports, provider cost reconciliation, route history and change previews, SSO group-mapping previews, access requests and the hold review queue of a workspace.

## Conventions

- **Sessions**: sign-in creates a session in an `HttpOnly` cookie. It ends 12 hours after sign-in or after 2 hours without activity, whichever comes first, unless the operator changed them. Every request rechecks the person's live role and memberships. Sign-in itself is rate-limited (see [Errors and limits](/docs/api/errors-and-limits#sign-in-limits)).
- **Changes** made with a session (anything but `GET` and `HEAD`) must send an `Origin` header that exactly matches the gateway's public URL and an `X-CSRF-Token` header equal to the `omg_csrf` cookie. Requests authenticated with an admin API token don't need either. No CORS is enabled.
- **Authorization first.** From v0.7.0 every route has an explicit access policy, checked against your live role before the request body is read. A route without one is refused even to Platform Admins.
- **Errors**: `{"error": {"code": "<HTTP status>", "message": "…", "reason": "…"}}`. `code` is always the HTTP status as a string; `reason` is a stable machine code for selected cases, such as `key_lifetime_exceeds_maximum`, `setting_locked_by_environment`, `exceeds_parent_budget`, `route_unsupported_capability`, `price_meters_incomplete` (which adds `missing_meters`) or `key_issuance_limit_exceeded`. Match on `reason`, not `code`. See [Errors and limits](/docs/api/errors-and-limits#management-api-errors).
- **Unknown fields** in a JSON body are refused.
- **Lists**: `{data: [...]}`, `limit` 1 to 200 (default 100) and `offset` (0 to 100,000). Financial lists add `has_more`. Logs, sessions, holds and route history use an opaque `cursor` instead; from v0.10.0 a cursor outside PostgreSQL's date range is `400`. Large lists are searched on the server with `q` rather than loaded whole (below).
- **Search text**: `q` (and the file list's `search`) is up to 200 characters. From v0.10.0 a control character in it is refused with `400`; whitespace only means no filter.
- **Integers** must be JSON integers, without a fraction, exponent or `-0` (an `offset` of `-0` is read as 0).
- **Slow reads**: lists of platform users, a user's detail, workspaces, and a workspace's members, keys and service accounts read from the same snapshots as reports. A statement that runs over 10 seconds is cancelled with `503` "The request took too long; narrow it and try again" (from v0.5.0).
- **Money**: integer micro-dollar amounts as **strings**, such as `"1250000"` for $1.25. Unknown values are `null`, never 0.
- **Dates**: UTC. Reports take `start_date` and `end_date` as `YYYY-MM-DD`, end excluded, 1 to 93 days.
- **Privacy**: no response ever contains a credential, a secret reference, a plaintext key, a prompt or a response.

## Denial responses

Releases v0.7.0 and v0.9.0 changed some refusals. They grant no new access, but automation that matches on status codes needs to know:

| Case | Answer | Before |
|---|---|---|
| Another person's personal workspace, on any `/workspaces/{ws}` route, for anyone including Platform Admins and Auditors | `404`, exactly as for an unknown id (v0.9.0) | `403` |
| A non-admin member rotating another person's key, in any state | `404` (v0.7.0) | `403` for an active key |
| A workspace admin rotating another person's disabled key | `403` (v0.7.0) | `409 key_disabled` |
| A Platform Auditor who isn't a member, on a workspace's key-limit routes | `403` before the key is looked up (v0.7.0) | `404` |
| A non-admin on a Platform-Admin-only workspace action | `403` before the workspace is looked up, even for an unknown id (v0.7.0) | |
| A malformed workspace or key id in the path | `404` (v0.7.0) | |
| A plain member managing a service account's key | `403` | |

Platform Admins and Auditors still see personal workspaces' totals in platform reports; the `404` only applies to the workspace's own routes.

## OpenAPI documents

From v0.10.0 the repository carries drift-checked OpenAPI 3.1 documents:

- [`docs/openapi/management.openapi.json`](https://github.com/ncecere/open-model-gateway/blob/v0.10.0/docs/openapi/management.openapi.json): every management route (251 operations), including each route's access policy and admin API token scope, generated from the gateway's route policy and checked against the real handlers.
- [`docs/openapi/inference.openapi.json`](https://github.com/ncecere/open-model-gateway/blob/v0.10.0/docs/openapi/inference.openapi.json): the supported inference API (27 operations).

Rules JSON Schema can't express are described in each operation and in `x-omg-*` extensions, which code generators ignore; the extensions are listed in the documents' READMEs beside them. For example, `x-omg-integer-encoding: "json-integer-literal"` records that integers must be JSON integer literals, which ordinary schema validators don't check.

## Added in v0.7.0 to v0.10.0

All under `/api/v1`.

### Admin API tokens (v0.8.0)

| Route | Who | Does |
|---|---|---|
| `GET /platform/admin-tokens` | Admin, browser session | Every token's metadata, never the token or its hash. |
| `POST /platform/admin-tokens` | Admin, browser session | `{name, scopes, expires_in_days (1–90), ip_allowlist?}`. Creates a token for yourself and returns `{id, token, scopes, created_at, expires_at}` once, with `Cache-Control: no-store`. |
| `DELETE /platform/admin-tokens/{token}` | Admin, browser session | Revokes a token. Any Platform Admin may revoke any token. |

Scopes are `platform:read`, `catalog:write`, `access:write`, `governance:write` and `settings:write`; a write scope doesn't include reading.

### Workspaces, access and keys (v0.9.0)

- `PUT /platform/workspaces/{ws}/discoverable` (Admin): `{discoverable: true|false}` for a Team or Project.
- `GET /access-request-targets` lists discoverable workspaces you aren't in. `POST /me/access-requests` takes `{workspace_id, idempotency_key, reason?}` (reason up to 1,000 characters); `…/{id}/withdraw` withdraws one. Owners and admins approve or deny at `/workspaces/{ws}/access-requests/{id}/approve` or `/deny`, Platform Admins at `/platform/access-requests/{id}/…`. Too many requests: `429` with `reason:"access_request_rate_limited"` and `Retry-After`.
- `GET /workspaces/{ws}/key-issuance` reports your key issuance in the last 24 hours (and the workspace's, for its admins). Creating or rotating a key past a limit answers `429` with `reason:"key_issuance_limit_exceeded"` and `Retry-After`. Policy bodies gain `key_issuances_per_holder` and `key_issuances_per_workspace`.

### Group mappings and routes (v0.9.0)

- `POST /platform/oidc/group-mappings/preview` and `POST /platform/oidc/group-mappings/{id}/preview` (Admin, browser session) dry-run a new, changed or deleted mapping, with `immediate` and `diff` results and, for an existing mapping, a `digest`. Send it back as `If-Match: "<digest>"` on the `PATCH` or `DELETE`: a changed mapping is then refused with `412 reason:"precondition_failed"`.
- `POST /platform/deployments/{id}/configuration/preview` (Admin, browser session) takes `{"enabled": true|false}` and returns the change's effect on serving routes and Teams and Projects, without writing anything.
- `GET /platform/deployments/{id}/configuration/history` and `…/history/{change}` (Admin and Auditor, browser session) list a route's enablement changes, with `limit` (1–100) and `cursor`.

### Alerts, holds, reports and costs (v0.9.0)

- `/platform/alerts/webhooks`: list, create, change (`PATCH`) and delete saved webhooks; `…/{id}/test` queues a test; `…/{id}/deliveries` returns the 50 newest deliveries. Tokens need `platform:read` to read and `settings:write` to change. Only Admins (and tokens with both scopes) see URLs and signing references.
- `GET /workspaces/{ws}/holds` and `GET /platform/holds`: requests unknown for 24 hours or more, with `limit` and `cursor`.
- Scheduled reports at `/platform/report-schedules` and `/workspaces/{ws}/report-schedules`, with their `runs` and aggregate `csv`. Creating or resuming past the schedule limit is `409 reason:"report_schedule_limit_reached"`; a CSV over 1,000 rows is `422`, and an expired one `410`.
- Provider cost imports, mappings and reconciliations under `/platform/provider-cost-…` and `/platform/provider-reconciliations` (Admin writes, Admin and Auditor read).

### Behaviour changes (v0.10.0)

- `POST /platform/settings/email/test` to a relay that isn't on the operator's host allowlist records and returns a failed test with `error: "host_not_allowed"`, instead of `409`.
- Support and logo URLs over 2,048 characters once percent-encoded are `400`.
- Control characters in search text, group-mapping issuers (which also refuse whitespace) and model and catalog descriptions (other than tab, line feed and carriage return) are `400`.
- Manual reconciliation with incoherent token counts is `400`.

## Added in v0.5.0 and v0.6.0

All under `/api/v1`.

### Your sessions and your data

| Route | Does |
|---|---|
| `GET /me/sessions` | Your live dashboard sessions, current one first: `{data: [{id, client, created_at, last_seen_at, expires_at, current}]}`. `id` is a handle, never the token; `client` is a browser and OS family, or `null`. No IP address. |
| `DELETE /me/sessions/{id}` | Signs one of your sessions out, including the current one: `{revoked: 1}`. Someone else's, an unknown or an ended session is `404`. |
| `POST /me/sessions/revoke-others` | Signs out all your other sessions: `{revoked: n}`. |
| `GET /me/export?from=YYYY-MM-DD&to=YYYY-MM-DD` | Your data as one JSON file (format `omg.subject-export.v1`), with requests and audit entries for up to 93 days, ending today or earlier (default the last 30). `X-OMG-Export-SHA256` is its checksum. 3 an hour (`429` beyond), `400` for a bad range, `503` when exports are busy. |
| `GET /me/models?limit=6` | The models added in your workspaces, for Home: `models` (up to `limit`, 1 to 50) with a serving route, `usable_count`, `not_serving`, `not_serving_count` and `workspaces_without_models`. |
| `GET /me/summary?totals_only=true` | Only your totals, without the per-workspace breakdown, which grows with the number of workspaces. |

### People, data and holds (Platform Admins and Auditors)

| Route | Who | Does |
|---|---|---|
| `GET /platform/users/{id}` | Admin, Auditor | Now also `active_sessions` (a count) and `legal_holds` (active holds, a count). |
| `POST /platform/users/{id}/sessions/revoke` | Admin | Signs the person out everywhere: `{revoked: n}`. `404` for an unknown or cleaned-up user. |
| `GET /platform/users/{id}/export` | Admin, Auditor | The person's record as admins see it: profile, platform roles, Team and Project memberships, platform audit entries. 3 an hour per caller. |
| `POST /platform/users/{id}/remove-personal-data` | Admin | Runs the account cleanup now. `409` while the person is active, already cleaned up, or on legal hold. |
| `GET /platform/legal-holds[?state=all]` | Admin, Auditor | Active holds, or all of them with `state=all`. |
| `POST /platform/legal-holds` | Admin | `{user_id, reference}` or `{workspace_id, reference}`; returns `201` with the hold's `id`. `400` for a bad reference or a personal workspace, `409` for a duplicate active hold or a person whose data was removed. |
| `POST /platform/legal-holds/{id}/release` | Admin | Releases a hold; `409` if it was already released. |
| `GET /platform/settings/audit-export` | Admin, Auditor | The audit export's status, including `transport` (`webhook`, `syslog`, `otlp` or `null`) and `next_seq`. |
| `POST /platform/settings/audit-export/test` | Admin | One test delivery: `{ok, error}`. `409` when export isn't set up; 2 a minute per admin and 20 an hour. |

### Workspaces and search

- `GET` and `PATCH /workspaces/{ws}` carry `object_visibility` on Teams and Projects: `member` (Per user, the default) or `workspace` (Workspace-wide). Owners and admins change it; any other value is `400`, and a personal workspace is `409 reason:"personal_workspace_visibility_fixed"`. See [Files](/docs/api/files#visibility).
- `q` (up to 200 characters, case-insensitive) searches member lists (`GET /workspaces/{ws}/members`, `GET /platform/workspaces/{ws}/members`) by email and display name, the key list (`GET /workspaces/{ws}/keys`) by key name, and `GET /platform/models` by API or display name.
- `GET /platform/workspaces/{ws}/member-candidates?q=` is the member picker for Platform Admins, as `GET /workspaces/{ws}/member-candidates?q=` is for workspace admins: up to 20 active people with a platform role who aren't members yet, matched on email.
- `GET /platform/models` also takes `not_in_catalog=<catalog id>` and `not_direct_in=<workspace id>`, to leave out models already in a catalog or assigned to a workspace.
- Audit rows name their actor, workspace and target (`actor_name`, `workspace_name`, `target_name`), and key rows their holder (`issued_to_name`), so the dashboard needn't load every user or workspace.

The complete route list, with bodies and responses, is in the [OpenAPI document](#openapi-documents) and the repository's [`docs/management-api.md`](https://github.com/ncecere/open-model-gateway/blob/v0.10.0/docs/management-api.md) and [`docs/governance-api.md`](https://github.com/ncecere/open-model-gateway/blob/v0.10.0/docs/governance-api.md).

## SCIM

SCIM 2.0 is a separate API at `/scim/v2`, authenticated with its own bearer token, for identity providers. Admin API tokens can't use it. See [SCIM provisioning](/docs/administration/scim).
