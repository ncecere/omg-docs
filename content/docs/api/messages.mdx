---
title: Messages
description: POST /v1/messages, the text and tool subset of Anthropic's Messages API, for Anthropic and Amazon Bedrock routes.
---

```http
POST /v1/messages
anthropic-version: 2023-06-01
x-api-key: omg_...
```

```json
{
  "model": "example/assistant",
  "max_tokens": 200,
  "system": "You answer in one sentence.",
  "messages": [{"role": "user", "content": "What is a cache write?"}]
}
```

Messages is served by models whose route is on an **Anthropic** or **Amazon Bedrock** connection. Point the Anthropic SDK at the gateway's address (without `/v1`); it sends the right version header.

## Headers

- `anthropic-version` must be exactly `2023-06-01`. Beta headers (`anthropic-beta`) are refused.
- Authenticate with `x-api-key` **or** `Authorization: Bearer`, not both.

## Request fields

| Field | Supported |
|---|---|
| `model`, `messages` | Required. Text content and text blocks; assistant `tool_use` with object input; user `tool_result` with text. |
| `max_tokens` | Required, positive. |
| `system` | Supported. |
| `temperature` | 0 to 1. |
| `stream` | Supported (see below). |
| `tools`, `tool_choice` | Supported: `auto`, `none`, `any` or a named tool, within each provider's limits. |
| `metadata.user_id` | A [Logs label](/docs/using/calling-the-api#label-sessions-and-apps-for-logs) only. Other `metadata` fields are refused. |

Refused: extended thinking, images and audio, cache-control settings, tool results marked as errors, and unknown fields. The gateway accounts for prompt caching when the provider reports it, but you can't ask for caching through it.

## Streaming

`"stream": true` works with the SDK's stream helpers. From v0.5.0, text streams as it is generated:

1. `message_start` is sent as soon as the upstream stream opens, before any usage is known. Its `usage` is the placeholder `{"input_tokens": 0}`.
2. Text is sent as `text_delta` events in content block 0 as it arrives.
3. Tool calls are sent whole, as `tool_use` blocks, after the text.
4. `message_delta` carries the observed usage: input tokens, cache counts and output tokens. The Anthropic SDKs apply it. `message_stop` follows.

Read usage from `message_delta`, not `message_start`: a client that reads only `message_start` sees 0 input tokens. If the provider never reports input tokens, the placeholder 0 is all a client gets; the gateway itself records the count as unknown, not zero. Other counts that weren't reported are left out. The output is still limited to 4 MiB, and an error before completion sends only an `error` event.

Before v0.5.0, the gateway collected the whole response first, and `message_start` carried the input and cache counts.

## Amazon Bedrock

On Bedrock routes the request goes through Converse: system messages only at the start, no assistant prefill, function tools with object schemas (no strict mode), and `tool_choice: none` is refused. Tool results are passed as text exactly as sent.
