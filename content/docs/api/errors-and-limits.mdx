title: Errors and limits
description: Error codes and HTTP statuses of the inference API, which ones to retry, sign-in rate limits, management API errors and the size limits.
---

Errors use the OpenAI shape, or Anthropic's on `/v1/messages`:

```json
{"error": {"message": "Budget for this API key would be exceeded in its current period", "type": "insufficient_quota", "code": "budget_exceeded", "param": null}}
```

Messages are fixed strings. They never contain provider error text, amounts, identities or how much budget is left.

## Codes

| HTTP | `code` | Meaning | Retry |
|---|---|---|---|
| 400 | `invalid_request_error` | A field or value outside the supported subset, or malformed input. | No: fix the request |
| 400 | `upstream_rejected` | The provider refused the request (validation, moderation, unknown model). | No |
| 400 | `unsupported_capability` | Images, audio, rerank, System One, realtime, files, batches and videos: no route can serve this request. | No |
| 401 | | Missing, repeated or invalid key, or a disabled, revoked or expired one. | No |
| 403 | `file_not_owned`, `batch_not_owned`, `video_not_owned` | From v0.6.0. Deleting a file or video, or cancelling a batch, that this key can see but didn't create, in a Team or Project, without being an owner's or admin's key or a service-account key. Type `permission_error`. | No |
| 404 | `model_not_found` | No such model, or not available to this key. (A model whose routes are only cooling down answers `503 model_temporarily_unavailable` instead, from v0.3.1.) | No |
| 404 | `not_found` | A file, batch or video id that doesn't exist, belongs to another workspace or, from v0.6.0, is hidden from this key by its Team's or Project's [visibility setting](/docs/api/files#visibility). Also for such a file used as `input_file_id`. | No |
| 413 | `payload_too_large`, `file_too_large`, `storage_quota_exceeded` | The body, file or workspace storage is over its limit. | No |
| 429 | `rate_limit_error` | A per-minute or at-once limit, or the provider's rate limit. | Yes, later |
| 429 | `job_limit_exceeded` | A "jobs at once" limit (batches, videos). | Yes, when a job ends |
| 429 | `token_reservation_exceeds_limit` | The model's input plus output ceiling is larger than a tokens-per-minute limit. | No |
| 429 | `budget_exceeded` | A budget would be exceeded in its current window. | No |
| 429 | `unresolved_usage` | Unknown, unbounded costs block budgeted requests. | No |
| 501 | `unsupported_capability` | Chat Completions, Responses, Messages and embeddings: no route supports the requested features. | No |
| 502 | `upstream_unavailable`, `invalid_upstream_response` | The provider failed or answered with something invalid. | Maybe |
| 503 | `provider_configuration_error` | Configuration problem: a missing credential, a budgeted request on a route with no price, or a request without an output maximum on a priced model. | No |
| 503 | `price_unbounded` | From v0.3.2. A budget applies, but the route's price can't bound this request: a meter it could use has no price, is priced as unknown, or has no maximum. Only an administrator publishing a complete price fixes it. Reports no scope or amount. | No |
| 503 | `model_temporarily_unavailable` | Every route of this model is cooling down after repeated failures. `Retry-After` gives the seconds until the first one reopens. On `/v1/messages` the type is `overloaded_error`. | Yes, after `Retry-After` |
| 503 | `accounting_unavailable` | The gateway couldn't record the request. | Maybe |
| 504 | `timeout_error` | The request deadline passed (120 seconds unless the operator changed it). | Maybe |

`price_unbounded` uses the type `price_unbounded` (on `/v1/messages`, `api_error`). Budget denials use the type `insufficient_quota`; `token_reservation_exceeds_limit` and `job_limit_exceeded` use `rate_limit_error`. On `/v1/messages` every 429 has Anthropic's `rate_limit_error` type, and the message says which case applies.

### Don't retry what can't succeed

`budget_exceeded`, `unresolved_usage`, `token_reservation_exceeds_limit` and `price_unbounded` responses carry `x-should-retry: false`. The official OpenAI and Anthropic SDKs honour it and don't retry. Errors from the Files API, except 503s, carry it too.

### Which scope refused

A limit denial names the scope kind: this API key or this workspace (there is no installation-wide budget or rate limit to refuse from v0.4.0). When several refuse at once, the narrowest is reported (key, then workspace), and budget denials come before rate limits.

Before v0.3.2, a budgeted request on a price that couldn't bound it was reported as `429 budget_exceeded`. It is now `503 price_unbounded`, because the cause is the price's configuration, not anyone's spending. Without any budget, such a request still runs, and its cost may be recorded as unknown.

## Sign-in limits

From v0.6.0, dashboard sign-in (`/api/v1/auth/login` and `/api/v1/auth/callback`) is rate-limited. These limits never apply to API keys.

| HTTP | When |
|---|---|
| 429 | Too many sign-in starts or callbacks from one client address: 60 a minute each, per gateway replica, unless the operator changed it. |
| 503 | Too many sign-ins are pending across the installation at once (about 10,000). Existing sessions keep working. |

Both carry `Retry-After` with the seconds to wait, store nothing and set no cookie. Behind a reverse proxy the operator must set `GATEWAY_TRUSTED_PROXIES`, or every user shares the proxy's limit; see [Identity setup](/docs/self-hosting/identity).

## Management API errors

The dashboard's [management API](/docs/api/management-api) uses a different shape. `error.code` is the HTTP status as a string, and `error.reason`, when present, is the stable machine code:

```json
{"error": {"code": "400", "reason": "price_meters_incomplete", "missing_meters": ["search_units", "requests"], "message": "…"}}
```

Reasons added in recent releases:

| HTTP | `reason` | When |
|---|---|---|
| 400 | `route_unsupported_capability` | From v0.3.2. Creating a route, enabling one, or changing a model's protocols would leave an enabled route on a connection whose profile can't serve the model. The message names the profile, the model's type and what the profile serves. See [Models and routes](/docs/administration/models-and-routes#routes-must-be-servable). |
| 400 | `price_meters_incomplete` | From v0.3.2. A published price leaves out a meter the route can use. `missing_meters` lists them. See [Pricing](/docs/administration/pricing#every-meter-must-be-stated). |
| 409 | `personal_workspace_visibility_fixed` | From v0.6.0. Setting `object_visibility` on a personal workspace, which has no such setting. |
| 410 | `installation_limits_removed` | From v0.4.0. `GET`/`PUT /platform/installation/policy` no longer exists: there is no installation-wide budget or rate limit. Use workspace-type defaults, platform overrides or key limits, and an [Installation spend alert](/docs/administration/alerts#installation-spend) to watch total spend. See [Limits and budgets](/docs/administration/limits-and-budgets). |

## Size limits

Unless the operator changed them:

| What | Limit |
|---|---|
| JSON request body | 2 MiB |
| Image generation, rerank, System One, speech request body | 2 MiB each |
| Transcription upload | 25 MiB file, 26 MiB request |
| Files API upload | 200 MiB |
| Batch input | 50,000 lines, 4 MiB each |
| Provider response | 4 MiB (images: 20 MiB) |
| Embeddings | 128 inputs, 1 MiB of text in total |
| Request deadline | 120 seconds |

The operator's settings are in [Configuration](/docs/self-hosting/configuration).
