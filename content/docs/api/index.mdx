Open Model Gateway has two HTTP APIs:

- **The inference API** under `/v1`, authenticated with [API keys](/docs/using/api-keys). It follows the OpenAI API, plus Anthropic's Messages API, so the official SDKs work against it. This reference covers it.
- **The management API** under `/api/v1`, used by the dashboard with browser sessions and, from v0.8.0, by scripts with [admin API tokens](/docs/administration/admin-api-tokens). API keys can't use it. See [Management API](/docs/api/management-api).

<Callout title="A supported subset, on purpose">
  Each endpoint accepts a documented subset of the vendor's API, and each provider supports a subset of that. Anything outside it is refused with an error, never silently dropped or changed, except where a page says a field is accepted and dropped. This reference is written by hand from the gateway's source. From v0.10.0 the repository also carries a drift-checked OpenAPI 3.1 document of the supported inference API, [`docs/openapi/inference.openapi.json`](https://github.com/ncecere/open-model-gateway/blob/v0.10.0/docs/openapi/inference.openapi.json) (27 operations), checked against the running gateway and the official OpenAI and Anthropic SDKs.
</Callout>

## Endpoints

| Method and path | What it does | Providers |
|---|---|---|
| `GET /v1/models` | [Models this key can use](/docs/api/models) | |
| `POST /v1/chat/completions` | [Chat Completions](/docs/api/chat-completions), streaming or not | OpenAI, Anthropic, Bedrock, OpenRouter, self-hosted |
| `POST /v1/responses` | [Responses](/docs/api/responses), stateless | OpenAI |
| `POST /v1/messages` | [Anthropic Messages](/docs/api/messages), including Claude Code | Anthropic, Bedrock; from v0.9.0 also OpenAI, OpenRouter and self-hosted, translated through Chat Completions |
| `POST /v1/embeddings` | [Embeddings](/docs/api/embeddings), float or base64 | OpenAI, OpenRouter, self-hosted |
| `POST /v1/images/generations` | [Image generation](/docs/api/images), base64 only | OpenAI (`gpt-image-*`), OpenRouter |
| `POST /v1/audio/transcriptions` | [Speech to text](/docs/api/audio#transcriptions) | OpenAI, OpenRouter |
| `POST /v1/audio/speech` | [Text to speech](/docs/api/audio#speech) | OpenAI, OpenRouter |
| `POST /v1/rerank` | [Rerank](/docs/api/rerank) | OpenRouter, self-hosted (OpenAI-compatible, vLLM, SGLang) |
| `POST /v1/systemone` | [System One decisions](/docs/api/system-one) | OpenRouter, self-hosted (OpenAI-compatible, Ollama) |
| `GET /v1/realtime` | [Realtime](/docs/api/realtime) WebSocket | OpenAI |
| `/v1/files` | [Files](/docs/api/files): upload, list, retrieve, content, delete | Gateway-owned |
| `/v1/batches` | [Batches](/docs/api/batches): create, list, retrieve, cancel | Any model |
| `/v1/videos` | [Videos](/docs/api/videos): no supported provider | |

Health checks (`GET /health/live`, `GET /health/ready`) need no key; see [Metrics and monitoring](/docs/self-hosting/metrics-and-monitoring).

## Conventions

- **Base URL**: your gateway's address plus `/v1`, for example `https://ai.example.edu/v1`.
- **Authentication**: `Authorization: Bearer omg_...`. `/v1/messages` also accepts `x-api-key` (one or the other, not both). Repeated or conflicting credentials are refused.
- **Workspace**: always the key's own. Requests can't name another.
- **Models**: the gateway's model names, such as `example/chat`, never the provider's ids. Responses return the gateway name too.
- **Body size**: JSON bodies are limited to 2 MiB, with per-endpoint limits for uploads and some workloads.
- **Integers** must be written as JSON integers: `100`, not `100.0`, `1e2` or `-0`. Other forms are refused with `400`.
- **Model names** with control characters, or longer than 2,704 bytes, answer `404 model_not_found` (from v0.7.0).
- **Errors** use the OpenAI shape `{"error": {"message", "type", "code", "param"}}`, or Anthropic's on `/v1/messages`. See [Errors and limits](/docs/api/errors-and-limits).
- **Unknown values are omitted, not zero.** If a provider didn't report a token count, the `usage` field leaves it out.
- **Optional labels** for Logs: `X-Session-Id` and `X-Title` headers. See [Calling the API](/docs/using/calling-the-api#label-sessions-and-apps-for-logs).

## Streaming

- Chat Completions streams token by token as server-sent events, ending with `data: [DONE]` only on success. An error mid-stream closes the stream without `[DONE]`.
- Responses and Messages stream text as it is generated (from v0.5.0); tool calls arrive whole, after the text. Messages streams start with placeholder usage, and the real counts come in `message_delta`. On native Anthropic routes, from v0.9.0, Messages also streams thinking blocks as they arrive. See [Responses](/docs/api/responses#streaming) and [Messages](/docs/api/messages#streaming).
- Closing the connection cancels the upstream request. The provider may still charge for work it did; the gateway keeps the hold until it knows.
- There is never a failover after a stream has started.

## Not supported

Request features that are refused with an error: images or audio inside Chat Completions and Responses messages (vision), structured output and JSON schemas, reasoning controls on Chat Completions and Responses, logprobs, `n` above 1, stored or background Responses, hosted and server tools (web search, file search, code execution), and referencing uploaded files in chat requests. On native Anthropic routes, from v0.9.0, Messages accepts base64 images, thinking and effort controls and prompt caching hints ([Messages](/docs/api/messages)).

Endpoints that don't exist return `404`, for example image edits and variations, fine-tuning, assistants, vector stores and moderation.
